接力包 Skill · 跨客户端任务接力

① 入口：先问清需求

  • 拆四要素：交付物 / 领域 / 关键动作 / 验收标准
  • 只问"不问就会做错方向"的项，最多 3 条
  • 能默认的给默认值 + "不接受就说不"
  • 需求确认前：不建卡、不选技能、不动手
  • 例外：一句话的小事直接做

② 接手：读状态，不追问

  • 只有一条命令：relay.py go
  • 有在办任务 → 直接接着干
  • 不再问已写进状态的目标 / 决策 / 边界
  • 没任务 → 转 ① 入口流程
  • 前提：各客户端在同一台机器、能读同一文件系统

③ 路由：本地优先，四级降级

  • ① 本地技能 — cap_index.py search（读索引，不逐个开 SKILL.md）
  • ② 本地知识 / 已有脚本
  • ③ 提示用户安装 — 结构化弹窗，同会话最多 1 次
  • ④ 自写脚本 — 过 audit 三绿才放行

④ 执行：定风格 + 压上下文

  • 风格档：严谨档 / 自适应档 / 参照档
  • style — 从历史任务卡现算用户画像
  • 上下文压缩 6 条：长内容落盘，对话只给路径 + 3 行
  • 结论先行，不复述、不预告、不写总结段
  • 能力检索只读索引，不重复读同一文件

⑤ 交付：两道门都过

  • 门 1 验证门：真跑入口、回读产物；"文件存在且非空"不算验证
  • 门 2 一致性门：核对是否与既定决策、上次产物矛盾
  • 发现冲突必须显式问，禁止静默改或两边都写

⑥ 沉淀：习惯留在本地

  • profile set — 只存稳定、可跨任务复用的偏好
  • 只写本地文件，绝不上传任何云端或第三方接口
  • 凭据、密钥、隐私内容一律不入画像
  • 换电脑：把 ~/.relay 拷过去即可

命令速查（relay.py）

命令作用关键点
go ★单入口：看状态 / 建卡 / 初始化日常只用这一条
init首次使用，建状态目录写 ~/.relay/tasks
doctor自检：能不能用、缺什么、状态在哪一眼看健康状态
new / set建卡 / 更新目标、决策、待办、产物、阻塞--decision 是关键
list / show / resume列出 / 全字段 / 输出续接包resume 是接手第一条
done收尾可带 --note
profile用户画像 show / set / del只写本地
style ★从历史任务卡现算风格画像不检索对话，任何客户端都能跑
audit ★自写脚本 B1/B2/B3 检查点填全 退出码 0；缺项 退出码 2

不适用（先说清边界）

  • 一次性小事（翻译一句、格式化一段）—— 直接做，建卡是负担
  • 用户明确只要对话、不要流程 —— 按对话走
  • 纯网页版 AI 读不到本地文件系统，参与不了接力
  • 它管流程与状态，不替你判断方案本身对不对

已知局限：注入块是文字指令，不是系统钩子 —— 能提高"AI 主动读状态"的概率，不保证 100%。
万一它没读，直接说一句 先跑 relay.py go 即恢复。
